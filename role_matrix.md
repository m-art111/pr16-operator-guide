# Матрица ролей

Источники: `data/service_spec.md` (SPEC-1.0), `data/operator_observations.md` (интерфейс 1.5.0).
Целевые роли руководства: **оператор** и **техник**. Остальные роли указаны только для того, чтобы показать, какие действия в руководство не входят.

## 1. Целевые роли

### Оператор (`operator_a`, `operator_b`)

| Действие | Разрешено | Элемент интерфейса | Ограничение / примечание |
|---|---|---|---|
| Просмотреть список своих заявок | Да | Экран «Заявки», фильтр «Мои» | Видны только собственные заявки |
| Создать заявку | Да | Кнопка «Создать» → экран «Новая заявка» → «Отправить» | «Тема» — 1–120 символов, «Описание» — 1–2000 символов (пробелы по краям не считаются) |
| Приложить файлы | Да | Поле «Вложения» | 0–3 файла, только PDF или PNG, каждый не более 5 000 000 байт, пустой файл не принимается, тип проверяется по содержимому |
| Открыть созданную заявку | Да | Ссылка «Открыть» в сообщении «Заявка LAB-… создана» | — |
| Открыть свою заявку из списка | Да | Экран «Заявки», строка с номером | См. открытый вопрос В-1 в `checkpoint_1.md` |
| Отменить создание | Да | Кнопка «Отмена» | — |
| Редактировать свою открытую заявку | Да, по спецификации | **В описании интерфейса нет** | В руководство не включено (элемент не описан) |
| Читать чужую заявку | Нет | Экран «Нет доступа к этой заявке» → «К списку» | Ограничение проверяет сервер, а не наличие кнопки |
| Удалить заявку | Нет данных | Кнопки удаления в описании нет | В руководство не включено |
| Назначить исполнителя | Нет | — | Делает менеджер |

### Техник (`technician_a`)

| Действие | Разрешено | Элемент интерфейса | Ограничение / примечание |
|---|---|---|---|
| Просмотреть назначенные заявки | Да | Экран «Заявки», фильтр «Назначенные» | Видны только заявки, где он указан исполнителем |
| Открыть назначенную заявку | Да | Строка в списке | — |
| Перевести open → in_progress | Да | Кнопка «В работу» | Только для назначенной заявки |
| Перевести in_progress → resolved | Да | Кнопка «Отметить выполненной» | Комментарий обязателен (непустой) |
| Удалить заявку | **Нет** | Кнопки удаления нет | Запрещено спецификацией |
| Читать неназначенную заявку | Нет | Экран «Нет доступа к этой заявке» | — |
| Сменить исполнителя | Нет | — | Делает менеджер |

## 2. Роли вне руководства

| Роль | Действия | Как отражено в руководстве |
|---|---|---|
| Менеджер (`manager_a`) | Видит все заявки, назначает исполнителя; не может незаметно менять автора и историю | Только упоминание: «исполнителя назначает менеджер» |
| Поддержка / администратор | Развёртывание, база, миграции, восстановление | Не описывается. Для оператора — «обратитесь в поддержку» |
| Неавторизованный пользователь | Ничего не читает и не создаёт | Предварительное условие: вход под своей учётной записью |

## 3. Словарь интерфейса

| Термин | Что это | Зачем нужно при работе |
|---|---|---|
| **Заявка** | Запись о проблеме: тема, описание, вложения, автор, статус, исполнитель | Создаётся одна заявка на одну проблему; её судьбу отслеживают по номеру |
| **Номер** | Идентификатор заявки вида `LAB-104`, выдаётся сервисом после сохранения | Только по номеру можно найти именно эту запись в списке. Не путать с номером кабинета («Проектор 204» — это тема, а не номер) |
| **Статус** | Этап работы: `open` (открыта) → `in_progress` (в работе) → `resolved` (выполнена) | Показывает, нужно ли что-то делать: техник берёт `open`, оператор ждёт `resolved` |
| **Вложение** | Файл PDF или PNG, приложенный к заявке | Помогает технику понять проблему. Не более 3 файлов, до 5 000 000 байт каждый |
| **Исполнитель** | Техник, которому менеджер назначил заявку | Если поле заполнено — заявка уже у техника; оператору повторно создавать её не нужно |
